# Pluto / Nano SDR: Zynq-7010 + AD9363, 1 TX / 1 RX

`pluto_simple.py` додає запис **одного RX-каналу** через pyadi-iio / libiio.
Файл обробляється тим самим GSM-декодером, що й у версії HackRF.
Програма виконується на комп'ютері; обчислення GSM не переносяться у FPGA Zynq.

Потрібна прошивка клона, сумісна з Pluto та стандартними IIO-пристроями
`ad9361-phy`, `cf-ad9361-lpc` і драйвером `adi.Pluto`.
Назви мікросхем самі по собі не підтверджують сумісність прошивки конкретної плати.
Програма не прошиває плату, не активує другий канал та не запускає TX/DDS.
Налаштування sample rate через pyadi-iio може змінювати спільні тактові частоти/FIR
AD9363; під час запису інші програми не повинні використовувати цей пристрій.

## Встановлення у Debian 12

```bash
git clone --branch codex/hackrf-simple https://github.com/romeo111/IMSI-catcher.git
cd IMSI-catcher
sudo apt update
sudo apt install python3 python3-venv gr-gsm libiio0 libiio-utils
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install -r requirements-pluto.txt
python pluto_simple.py doctor
```

Якщо форк уже завантажено, оновіть цю гілку командою `git pull --ff-only`, потім
встановіть залежності. `--system-site-packages` потрібний, щоб середовище бачило GNU Radio
та gr-gsm, встановлені через apt. `pip install adi` не замінює `pyadi-iio`.

`doctor` імпортує бібліотеки, але не підключається до пристрою. Для комп'ютера,
на якому тільки записуються IQ, доступний `python pluto_simple.py doctor --capture-only`.

## Підключення

За замовчуванням URI — `ip:192.168.2.1`. У клона може бути інша адреса.
Доступні способи підключення визначає його прошивка: USB через libiio або мережевий URI.

```bash
iio_info -s
iio_info -u ip:192.168.2.1
```

Якщо в переліку є USB URI, його можна передати безпосередньо, наприклад
`--uri usb:1.2.5` (замініть на URI з вашого переліку).
Для плати з Ethernet вкажіть її фактичну адресу: `--uri ip:АДРЕСА_ПЛАТИ`.
Автоматичне виявлення USB може потребувати правил udev; мережевий URI — доступності
служби IIO пристрою з комп'ютера.

## Запис та обробка

Частота нижче — **приклад**. Замість неї вкажіть центральну частоту GSM C0
вашої тестової мережі або дозволеного джерела сигналу.

```bash
python pluto_simple.py capture nano.cf32 --uri ip:192.168.2.1 --freq 935.2M --seconds 30
python pluto_simple.py decode nano.cf32
```

Файли: `nano.cf32` та `nano.cf32.json`. Частота, sample rate і формат завантажуються
під час декодування автоматично. Новий запис не перезаписує наявні файли.
Перший буфер після налаштування відкидається; кінцевий обрізається до потрібної кількості
відліків. Ctrl+C або помилка I/O залишає частковий файл і метадані `status=partial`.

| Параметр | За замовчуванням |
|---|---|
| RX | канал 0, один комплексний потік |
| Sample rate | 2 MS/s |
| RX RF bandwidth | 600 кГц |
| Режим підсилення | manual, 40 дБ |
| Буфер | 65536 комплексних відліків |
| Таймаут IIO | 5000 мс |
| Формат файлу | `cf32`, little-endian float32 I/Q без заголовка |
| Швидкість запису на диск | 16 МБ/с; приблизно 480 МБ за 30 с |

Значення IQ зберігаються як **raw ADC counts**, перетворені на float32; порядок I/Q
і знаки зберігаються. Квантування до int8, як у HackRF, немає. 12-бітні відліки AD9363
представляються в цьому форматі без втрати точності.
Частота, sample rate, смуга й підсилення в метаданих читаються назад із пристрою,
тому враховують округлення або обмеження драйвера.

Приклад додаткових параметрів:

```bash
python pluto_simple.py capture nano2.cf32 --uri ip:192.168.2.1 --freq 935.2M --sample-rate 2M --bandwidth 600k --gain 30 --seconds 15
python pluto_simple.py decode nano2.cf32 --all-tmsi --assignments --jsonl nano-observations.jsonl
```

`--gain` приймає 0–70 дБ; апаратні межі залежать від частоти й драйвера.
Зменшуйте gain при перевантаженні. `--sample-rate` приймає 1M–20M, але досяжна
безперервна швидкість залежить від USB/мережі, прошивки та диска; для однієї GSM-несучої
починайте з 2M. `--bandwidth` задає смугу RX-фільтра, а не частоту дискретизації.

Підтримуваний діапазон тюнінгу — стандартні **325 МГц–3.8 ГГц AD9363**.
Розширення діапазону зміною прошивки не потрібне для GSM-900/1800 і не входить у цю версію.
Див. [параметри AD9363](https://www.analog.com/en/products/ad9363.html) і
[інтерфейс Pluto у pyadi-iio](https://github.com/analogdevicesinc/pyadi-iio/blob/v0.0.21/adi/ad936x.py).

## Windows / WSL

Для нативного запису у Windows потрібні Python, залежності з `requirements-pluto.txt`
та [нативна бібліотека libiio від Analog Devices](https://github.com/analogdevicesinc/libiio/releases)
відповідної архітектури. Сам `pylibiio` з pip не встановлює нативну DLL.
Після встановлення перевірте `python pluto_simple.py doctor --capture-only`.
Доступність URI перевіряється через `iio_info`.

Декодування виконуйте у Linux/WSL з GNU Radio/gr-gsm. Передавайте разом IQ і сусідній
JSON-файл. Для обробки готового файлу передавати USB-пристрій у WSL не потрібно.
Для запису через WSL мережевий URI має бути доступним із WSL; direct USB потребує
підключення пристрою саме до WSL.

## Перевірки та межі

```bash
python -m unittest discover -s tests -v
```

Тести використовують модель одного RX, перевіряють порядок I/Q, точний розмір,
фактичний sample rate, таймаути, Ctrl+C, відсутність перезапису та сумісність API
встановленого pyadi-iio. У CI також запускаються реальні графи GNU Radio для файлів
HackRF і Pluto. Це не перевірка RF-приймання на фізичній платі Nano SDR.

`status=complete` означає, що отримано потрібну кількість відліків. Він не доводить
відсутність пропусків між буферами: цей шлях pyadi-iio не додає часових міток DMA;
метадані явно містять `continuity=not_verified`.
Декодер працює з однією центральною GSM-несучою; автоматичний пошук, live-декодування,
frequency hopping та LTE/5G не реалізовані. Решта параметрів декодера описана в
[інструкції HackRF](HACKRF_UK.md).
